# A reading's meaning is declared, never taken from the shape its value happens to have

A reading is one named figure a report carries off a tape, and what a report is for is comparison: this build against that build, this configuration against that one, never a number against a target (ADR 0053). Three declines have now rested on the same unwritten rule. Slice G declined to let a new distribution ride on the peak's existing declaration and built a named reduction kind instead (`docs/push/step-4-progress.md` section 19, which also finds that what holds a new reading is the two declaration guards and not any module list). Slice H declined to let a shove's one report carry the distance the push asked for rather than the distance the body was really carried (`docs/push/round-two-progress.md` section 8). Slice I declined to infer which push threw a body from the wave spacing its impulse happened to carry, and states the rule in words (same note, section 9).

**A reading means what its own entry in the declaration table says it means, and nothing else.** Two tables declare it: `READING_COMPARISONS` says what comparing the reading means, and `BATCH_READINGS` says how a batch reduces it. What is forbidden is a comparison, a batch reduction, a report or a test taking a reading's meaning from the shape, range, sign or type its value happens to have. An array of numbers is a per-tick series only where its reading says so, and a discriminator is a field its producer writes rather than a pattern its consumer recognises, even where the pattern is reliable today. A reading with no entry is a hole, not a default.

The guard is `src/dev/__tests__/comparisonDeclared.test.ts`, and it pins the rule in both directions: every reading a verified report carries is claimed by a declaration, and every declaration names a path the report really carries, so a reading is never guarded by a name alone. The cost is deliberate and it is paid at the point a reading is added: a new reading is declared before it can be compared, and a cheaper inference is refused even where the tree would make it correct. This rule governs what a reading means. Whether a changed meaning moves `READINGS_VERSION` is that constant's own separate rule.
