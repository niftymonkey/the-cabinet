# The witness and the refusal rule

**Absorbed ADR 0015 on 2026-09-17 on Mark's ruling: determinism is the premise this record exists to prove, so it opens the record rather than standing beside it.** The simulation advances only in fixed ticks of sixty per second, the accumulator living in the game's own code so the harness and the rendered screen share one implementation, with catch-up clamped so a backgrounded tab cannot fire a burst of ticks the player has no chance to answer, and a run's length counted in ticks rather than wall clock. Seeded streams are the only source of dice, and one accidental `Math.random` breaks determinism outright. Every implementation-approximated operation goes through one module that rounds its result to single precision: engines are permitted to differ in the last bit on `sin`, `cos`, `tan`, `atan2`, `exp`, `log`, `pow` and in practice `hypot`, which is exactly the set a bell radius, a seeker's turn and a wisp's homing reach for, and this game's testers are on a phone and a desktop by construction, so two engines. A lint rule keeps the rest of the simulation from reaching around that module and from calling `Math.random` at all. The honest limit is that this makes divergence very unlikely rather than impossible, which is the strongest mitigation available short of a fixed-point simulation, and it is why the witness is a proof and not a formality. `math.ts` is the named way out if a real divergence ever appears: an integer-indexed sine table there would make the trig deterministic by construction.

A witness is the number a run folds its own state down to, stamped on a tape at checkpoints as the run goes, so a replay can recompute it and attest that it reproduced the run rather than merely resembling it. Each checkpoint is an independent snapshot rather than a link in a chain, so a replay that diverges can name the first checkpoint that disagrees and playback can be bounded by the last one that verified. The witness carries its own version byte, separate from the format version, because the fold demonstrably widens: without it, every tape recorded before a widening reports a divergence under the rule below and nothing distinguishes "the fold definition changed" from "this run did not happen".

**The witness is the only fidelity gate, and it refuses rather than degrades quietly.** In Mark's words: never show frames after the replay can no longer be verified as the original run, and the rules hash is for grouping and version context and must never block replay. For numbers, `measure(tape)` returns metrics or a divergence, so a silently wrong metric is not a thing the interface can produce. For watching, a replay plays through the last verified checkpoint and then stops and says so.

Two alternatives were rejected. Refusing everywhere, because once sharing ships every shared replay would die the moment anybody touched the simulation. Playing to the end with a version label, because after a divergence the frames are a different run wearing the player's name, and a label does not fix that. Two proxies were rejected as gates as well: the commit hash, since a typo in a README would invalidate every tape on a project that commits several times a day, and a build-time hash of `src/game`, which is precise about the rules and still only says they look the same rather than that the run came out the same, so a comment edit moves it while the run replays perfectly.

**Run integrity is a second gate and never the same gate.** The witness answers whether this is the original run; integrity answers whether the original run was sound, so a fault is not a divergence and `measure(tape)` does not refuse one: it returns the metrics together with the trailer's integrity and the recorded faults, and any aggregate that pools runs for tuning excludes faulted runs by default rather than treating them as healthy evidence. Refusing instead was rejected because the reason a recoverable fault lets the run continue is that a run which keeps recording is better evidence about the anomaly than a run that stops at it, and a `measure` that discarded the result would throw away exactly what that ruling exists to preserve.

Ruled by Mark across the analytics and replay grill on 2026-08-22 and the three review gates on #48 on 2026-08-23, and on determinism 2026-08-19. The argument is in [../design/analytics-and-replay-grill-2026-08-22.md](../design/analytics-and-replay-grill-2026-08-22.md).
