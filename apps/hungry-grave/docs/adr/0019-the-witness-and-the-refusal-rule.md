# The witness and the refusal rule

A witness is the number a run folds its own state down to, stamped on a tape at checkpoints as the run goes. A replay recomputes it and can therefore attest that it reproduced the run rather than merely resembling it, and a tape that cannot prove itself reports nothing rather than reporting wrongly. The fold moves out of `src/dev/digest.ts` into `src/game`, because a replay ships and Hungry Grave ADR 0013's rig must not be load-bearing in the shipped game (amended by Hungry Grave ADR 0017). It is one function with a starting-value parameter, used two ways rather than being two behaviours: chained across ticks for the golden scenario's accumulator, and as an independent snapshot for a tape's checkpoints. The digest is the witness of the one canonical scenario, so the two words name one fold with two uses.

**The fold covers everything the rules mutate, and the list is closed before the first commit.** The first draft named mob health, orbit phase, the stream cursors, score, the reservoir and the four weapon levels, and that list was incomplete in exactly the places the instrument is meant to read. The full list adds `stage.phaseIndex`, `stage.phaseTick` and `stage.firedRows`, because the authored stage cursor drives every spawn; `lines.streamIn`, `lines.surgeVolleys`, `lines.tollIn`, `lines.stoneRecharge[]` and `lines.ring.ticks`, which are three of the four weapon lines' own clocks and, in `stoneRecharge`'s case, the headstones line's real per-slot state that orbit phase alone does not cover; `mob.beat`, `mob.fireIn` and `mob.armed`, because a stream cursor catches a differing draw and not a differing countdown that reconverges; `wisp.life` and `wisp.targetId`, the line whose contribution Mark most wants attributed; `killsSinceDrop` and `dropsPaid`, the drop economy of Hungry Grave ADR 0002, since "when did a level actually land" is one of the questions the instrument exists for; `nextEntityId`, one integer summarising all spawn activity that catches a spawn-count divergence on the tick it happens; `grave.invulnerable` and `run.ending`; `ring.level`, which is captured at strike time and deliberately decoupled from `levels.bell` so that a level-up mid-ring cannot shove harder than the ring that is shoving reaches, meaning folding `levels` does not cover it; `corpse.payout`, `corpse.kind`, `corpse.tier` and `corpse.line`, which are the drop economy this list already says it is including for "when did a level actually land"; and `ring.struck`, the bell's per-ring set of ids it has already hit, which is mutated every tick and decides whether a mob takes damage at all, so a divergence in it is a divergence in the rules and not in a readout. Every one is a scalar, a short array or a small set, and all of them together are negligible beside the per-entity walk.

**The list stays closed by a completeness assertion that walks the nested types, not by diligence and not by `RunState`'s own keys.** `checkNoNaN` already enumerates most of these fields, so the tree carries two hand-maintained lists of "everything the rules mutate" and nothing fails when a field is added to one and forgotten in the other. Per-field tests only ever test the fields somebody remembered, so the assertion is the mechanism and the per-field tests are the evidence each field is actually folded. **An assertion over `RunState`'s own top-level keys catches nothing this widening adds**, because all eighteen of those keys already exist and every field named above lives one or more levels down, inside `StageState`, `LineState`, `Mob`, `Wisp`, `Grave` or `BellRing`. It already missed `ring.struck` on exactly that account. So the assertion walks the nested value types against a closed list rather than reading the outer object's keys, and a new field at any depth fails it.

**An assertion of that shape needs both halves of the partition, and naming only the folded half rebuilds the problem it exists to kill.** Every nested field is either folded or deliberately excluded, so the excluded half is written down with its reason beside it, and a field in neither list fails the assertion. Without that, "two hand-maintained lists of everything the rules mutate" simply becomes folded against excluded and nothing fails when a new field is added to neither. Both land in the same commit that regenerates `GOLDEN`, and that commit comes first, before any refactor: a constant blessed by a partial fold certifies the mistake, and every later comparison then runs against a wrong baseline. One cheap guard rides along with the regeneration. `score`, `reservoir` and `levels` are already top-level `Digest` fields, so widening the checksum to include them should move exactly one field of `GOLDEN`, and if the regeneration diff touches anything but `checksum`, something else changed and the commit is wrong.

**Seven of the widened fields are not numbers, and `fold` is numeric-only**, since it is `Math.imul(checksum, 31) + Math.round(value * 1e9)`. Whatever encoding is chosen becomes permanent the moment the first tape exists, so it is chosen here rather than at the keyboard. A **boolean** folds through an explicit helper to 0 or 1, never through arithmetic coercion, so the encoding is visible at the call site. A **`number | null`**, which is `wisp.targetId`, folds through a sentinel that cannot collide with a real id: `nextEntityId` starts at 1 and only ever increases, so 0 is unused and means no target. A **string union**, which is `run.ending`, folds through an explicit append-only code map pinned by its own test, and never by the member's ordinal position in the union, because reordering the union would then silently move every tape's witness with no version bump and no diff anybody would read as dangerous. A **set of ids**, which is `ring.struck`, folds its size and then its members in iteration order, which is deterministic here because insertion order follows the mob pool's slot order. And **`lines.ring` is itself nullable**, so the absent ring folds through its own sentinel rather than being skipped, or a run with no ring and a run whose ring folds to zero become the same witness.

**Three more string unions ride on the corpse and one of them is optional**, which an earlier draft of this paragraph missed while claiming the list was complete. `corpse.tier` is `CorpseTier`, `"trash" | "rich"` at `mobs.ts:42`; `corpse.kind` is `FoodKind`, `"corpse" | "drop" | "feast"` at `swallow.ts:26`; and `corpse.line` at `corpses.ts:56` is `WeaponLine` **and optional**. Each union gets its own append-only code map on the same terms as `run.ending`, never by ordinal. The optional one is the composition of two rules already here rather than a new one: **absent folds through a reserved code that no member of the union may ever take, and present folds through the map.** Skipping the field when it is absent would make a corpse with no line and a corpse whose line happens to fold to zero the same witness, which is the identical trap `lines.ring` carries. This paragraph is the agent's design rather than one of Mark's rulings, and it is recorded so that it is a decision somebody can overturn rather than an accident nobody notices.

**The fold runs at checkpoints only, and never on every tick.** Storing a fold per tick would localise a divergence to the exact tick and would cost 12,000 times 4 bytes, growing a full-stage tape from about 96KB to about 144KB. Checkpoints localise a divergence to one second and cost nothing. A divergence in this game compounds through the economy by Hungry Grave ADR 0015's own argument, since drops are priced in kills and one bent path crosses a drop price at a different moment, so it never self-heals and one second of granularity loses nothing that matters. The decision is one-way, because a replay has nothing to compare its own per-tick folds against. A related claim from the first draft is struck rather than carried: computing the fold on every tick while storing only checkpoints makes the intervening folds dead work and buys no better detection at all. CPU was never the deciding factor either way, and the decision survives the number moving underneath it: `foldEntities` measures 4 to 8 microseconds a tick, which was a fiftieth of the invariant checks at their first measurement of 298 to 372 and is about a fifth of them at the 23 to 37 they cost once `checkNoNaN` stopped allocating, and Hungry Grave ADR 0017 carries both figures. Bytes decided this, and the byte argument above is untouched by either of them.

**Each checkpoint is an independent snapshot rather than a link in a chain**, so `measure` can name the first failing checkpoint and playback can be bounded by the last one that verified. A chained fold only ever says that something went wrong somewhere before here.

**Checkpoint indexing is defined once and unambiguously: the checkpoint at index N is the fold of the state after `executeTick` has run N times.** Index 0 is therefore the state before any tick has run, and that is what "the very first tick is witnessed" means. An off-by-one here makes every tape refuse itself against a reader that counts the other way, and it cannot be fixed after tapes exist.

The checkpoint spacing is carried in the tape header rather than compiled into the reader, so a later measurement can move it without versioning the format. Hungry Grave ADR 0018 carries that and the rest of the header.

**The witness carries its own version byte, separate from the format version.** The fold demonstrably widens, this work is the proof, and a second widening is likely. Without a witness version, every tape recorded before a widening reports a divergence under the refusal rule below and nothing distinguishes "the fold definition changed" from "this run did not happen". StarCraft II and Widelands both block playback on a build fingerprint mismatch rather than letting it surface as a desync, which is the same instinct: refuse clearly rather than fail confusingly.

**Proving the witness works is verification readback, and verification readback is not replay.** A witness that has never been recomputed from a decoded tape is an untested claim, so the dispatch that writes the fold also reads one back: decode a tape, recompute the fold at its checkpoints, and reproduce the run far enough to show the same tape twice gives the same run. That is the proof and it is the whole of the capability. Hungry Grave ADR 0020 carries the boundary and the reason it is named this way rather than called a small replay, and the short version is that **no replay obligation is satisfied by this existing**.

**The witness is the only fidelity gate, and it refuses rather than degrades quietly.** In Mark's words: never show frames after the replay can no longer be verified as the original run, and the rules hash is for grouping and version context and must never block replay. For numbers, `measure(tape)` returns metrics or a divergence, so a silently wrong metric is not a thing the interface can produce. For watching, a replay plays through the last verified checkpoint and then stops and says so. Refusing everywhere was rejected because once sharing ships, every shared replay would die the moment anybody touched the simulation. Playing to the end with a version label was rejected because after a divergence the frames are a different run wearing the player's name, and a label does not fix that. Two proxies were rejected as gates as well: the commit hash, since a typo in a README would invalidate every tape on a project that commits several times a day, and a build-time hash of `src/game`, which is precise about the rules and still only says they look the same rather than that the run came out the same, so a comment edit moves it while the run replays perfectly.

**Run integrity is a second gate and never the same gate.** A tape can verify perfectly and still be poor evidence, because Hungry Grave ADR 0017 lets a recoverable fault record itself while the run carries on. The witness answers whether this is the original run; integrity answers whether the original run was sound. A fault is therefore not a divergence and `measure(tape)` does not refuse one: it returns the metrics together with the trailer's integrity and the recorded faults, and any aggregate that pools runs for tuning excludes faulted runs by default rather than treating them as healthy evidence. Refusing instead was rejected because the reason a recoverable fault lets the run continue is that a run which keeps recording is better evidence about the anomaly than a run that stops at it, and a `measure` that discarded the result would throw away exactly what that ruling exists to preserve.
