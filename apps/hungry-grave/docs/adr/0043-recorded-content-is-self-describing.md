# Recorded content is self-describing, so content can change without a format change

**A tape records the identity of the content its own bytes depend on, so that content can change without changing the wire format.** Where the meaning of a recorded value depends on which members a game concept currently has, the tape names those members rather than relying on the reader to supply them. The weapon roster is the first case: the header records the lines it was written against, and the starting levels are read against that recorded roster instead of against the reader's own. The rule is written for the concept and not for weapons, because stage identities, boss identities and any later content set whose membership a recorded value depends on are the same problem arriving again.

**This exists because compatibility machinery is here to protect iteration, not to constrain it.** Hungry Grave is expected to keep changing for a long time: lines, bosses, stages, systems, tuning and content nobody has designed yet. A recording architecture that turns each of those into a format break makes ordinary development progressively more expensive, and the project would then start choosing what to build by what the tape can afford. So the boundaries are divided by what actually changed rather than by what is easiest to version.

**Three boundaries, independent of each other, each answering one question.** The **format version** describes wire-layout semantics: the grammar of the bytes, what fields exist and in what order and of what width. The **witness version** (Hungry Grave ADR 0019) versions the deterministic fold and nothing else; it decides whether a replay can attest it reproduced the run, and it never decides how a header is interpreted. **Recorded content identity** is data inside the tape, and it carries the vocabulary a content-dependent value is written in.

**They are independent, not mutually exclusive, and a single game change may move one, two or all three.** The three questions are therefore asked separately rather than sorted into: did the wire grammar change, did the deterministic fold change, and did the recorded content vocabulary change. The weapon-line swap this record was written during moves all three at once, and it is the worked example: making the roster self-describing changes the wire grammar, so the format version moves; a new line adds state the rules mutate, so the fold widens and the witness version moves; and the roster's membership changes, so the recorded content vocabulary changes. **What the boundaries buy is not a tidy sort. It is that none of them may ever substitute for another**, so a fold version is never asked to explain a layout, a format version is never spent merely because the cast changed, and a recorded identity never certifies that a run will reproduce.

**A reader never reinterprets bytes under changed meanings.** This is the rule the other two serve, and it is the one that must never bend. Hungry Grave ADR 0018 already states the refusal contract for an unknown layout, that a reader refuses rather than guessing. The failure this record is written against is subtler and was found on 2026-08-27 while planning a weapon-line swap: a positional list keeps its byte count while its meaning moves underneath, so the layout looks unchanged and the decoder happily returns a value that is precisely wrong. Byte count is not the test. Whether a reader can name what a byte means without assuming its own present-day world is the test.

**Unknown recorded content may be reported truthfully, but a build that does not implement that content cannot replay it.** Reading and replaying are two different obligations and conflating them is what produces a wrong number. A tape naming a line this build does not implement is still readable: its header is reported as recorded, in the tape's own vocabulary, because the tape said something true and the reader's job is not to edit it. It is not replayable *by that build*, because a simulation cannot run a line it does not have, and Hungry Grave ADR 0019 already rules that a replay which cannot prove it is the original run reports nothing rather than reporting wrongly. The limit is the build's, not the tape's: whether some later build chooses to implement an older content set and replay it is a decision nobody has taken, and this record neither promises it nor forbids it. What this buys is a refusal that is precise rather than blanket: "this tape was recorded against a roster this build does not implement" instead of "unknown format", and a reader that still answers every question that does not depend on simulating the missing content.

**The identity says what the cast was, never that the rules are the same.** Two builds can name the same roster and behave differently, because a retuned curve changes no name. That gap is already covered and must not be covered twice: ADR 0019 rules that the witness is the only fidelity gate, and it rejected build fingerprints as gates on exactly these grounds. So the recorded identity answers interpretation and the witness answers fidelity, they are complementary, and neither is allowed to stand in for the other. This is also the boundary that keeps this record from growing into a general content-schema system: identity is recorded so bytes can be read honestly, and nothing more is claimed for it.

**Nothing generic is built ahead of a caller.** The concrete roster problem is solved and no schema machinery is built for content that does not exist yet, per the cited-future rule. What the record does bind is the shape of the next answer: a later content set whose membership a recorded value depends on is recorded the same way, and no new closed-world or positional assumption is introduced in the meantime. A positional list over an open set is the specific mistake, and the reason it is worth naming is that it was written down as permanent, obeyed for months, and still turned out to be a lie the moment the set it indexed was allowed to change.

**The accepted cost, recorded so it is never mistaken for an oversight.** Making the roster self-describing is itself a wire-layout change and therefore takes a format version, so every tape recorded before it stops decoding. That price is paid once, deliberately, at the point in the project where it is smallest: no tape has been shared with anyone and Hungry Grave ADR 0020's player-facing replay has not shipped. Reports already extracted from earlier runs are unaffected and stay comparable through the report-to-report seam, with build and provenance shown. The alternative, preserving the old version through ambiguous semantics, was rejected because it trades a one-time cost for a permanent one and pays in wrong numbers.
