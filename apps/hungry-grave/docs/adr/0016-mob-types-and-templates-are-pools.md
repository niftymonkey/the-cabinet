# Mob types and templates are pools

A mob type owns its own properties rather than being one entry in a fixed cast: how it moves, whether and how it fires, its health, its corpse payout, and its size. v1 ships three, the base trash where only a share of each wave fires at all, a tougher type that fires a damaging shot the moment it enters, and a type whose body is the threat and which turns toward the grave (ruled by Mark 2026-08-19, chosen over a type firing tracking shots, because homing pointed at the player takes away the answer positioning is supposed to be). The pool is open by design, the same treatment weapon lines got in Hungry Grave ADR 0005.

A template owns placement and entry, never who is in it. It says where a group arrives and how it is arranged; the mob type inside it supplies the motion and the firing. This is what lets both pools grow without multiplying into each other: a single-file lane of base trash falls in a line, and the same lane of the body-threat type arrives in a line and then turns, which is two completely different waves out of one template. The library is open on the same terms, and a new template has to teach a lesson no existing template teaches, or the library becomes six flavors of "some mobs come down". This supersedes the slice-era statements that the library is six shapes with the one trash mob playing all of them, and that the Undertaker's diggers are that one trash mob respawned.

Two rules keep a growing mob pool safe, and both are readability rules rather than content rules.

A mob type must be readable before it acts: its silhouette says what it does, one that will shoot looks armed rather than identical to one that never shoots, and its fire stays large, slow, irregular, and inside the value band Hungry Grave ADR 0014 reserves for mob fire.

And a mob holds the template's arriving motion for a beat before its own movement takes over, so the placement's lesson still reads no matter which type is flying it. The beat governs movement only and never firing (ruled by Mark 2026-08-19, scoping an earlier proposal that covered both). Firing is already governed by the rule above, and the two collided: a type whose identity is firing the moment it enters would have had that identity delayed by a rule meant to protect a lane's readability. Scoped this way the two compose, because such a type arrives flying the template's shape, its tell lights during the arriving beat, and then it fires, so the player gets the same warning window as information rather than as a pause.

Content stays counted in authored rows, never as mob types multiplied by templates, and count stays on the row rather than in the template (Hungry Grave ADR 0006). Live mobs are never food whatever their type: contact shrinks the grave and only kills leave corpses (Hungry Grave ADR 0005).

A set piece names the property it must keep, never the mob types allowed in it (ruled by Mark 2026-08-19, after all three review gates converged on it). Pinning the cast would rebuild the fixed-membership club this ADR exists to dismantle, at the one place the design cares most, and would forbid a perfectly good harder curtain built from base trash with the armed share turned up. Leaving it to the author fails silently, because a curtain of the type that fires on entry makes the unloaded crossing impossible while every test still passes.

The property is two-sided and both halves are load-bearing: an edge-to-edge curtain built as the belch's target stays crossable unloaded, and is never crossable for free. One-sided would let the curtain become comfortable, and then the loaded belch has no reason to be spent there and the run's most choreographed moment dies from the other direction. Two bot policies carry it, one crossing without belching and surviving at a real cost in size or hits, one belching and crossing clean. The unloaded policy is written as a plausible human rather than an optimizer, because a bot proof is an upper bound on perfect play and never a fairness result, so a human crossing stays the anchor.
