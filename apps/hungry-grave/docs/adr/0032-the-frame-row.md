# The frame row

Each rendered frame of a live run writes one row in the tape's observations section, because a per-run aggregate cannot answer which gameplay situations created a cost. The row is a minimum timing row and never a speculative telemetry schema: once tapes carry the row, changing its schema carries the format's compatibility cost (Hungry Grave ADR 0018), so a field nobody has a question for is bought at that price, and the counterweight (Hungry Grave ADR 0021) rules here as sharply as anywhere.

A row records what was actually observed at the frame seam, and unavailable context stays unavailable rather than fabricated. The seam lives inside a run's lifetime, since a tape is one run's recording and a run-less frame has no tape to be written into. A frame that bought no ticks has an absent tick index rather than an invented one, and the predicate is the tick purchase and never the pause: at a 120Hz refresh against the 60Hz tick rate roughly half of ordinary live frames buy no tick, so a null index says only that the frame bought nothing. The why is its own field: a reason byte from a closed list derived from the seam's real guard conditions, live, then ending, paused, backgrounded and countdown, recorded in the guard's own short-circuit order when more than one holds. Skipped frames are marked, never omitted.

The reason byte supersedes the ruling of 2026-08-23 that a paused frame's row is byte-identical to a live sub-tick frame's. What stood: the tick purchase as the index's only predicate, and absence recorded rather than invented. What that ruling could not have known: the minimal export would let a tape outlive its run in the same dispatch, and why a frame bought nothing is runtime history no replay rebuilds, so the row's own principle argues for writing it down.

The seam's guard topology and the hook's placement live as comments in `GameScreen.ts`. Extracted from Hungry Grave ADR 0018 on 2026-08-26, decision unchanged. Ruled by Mark 2026-08-23 and 2026-08-24; the argument is in [../design/analytics-and-replay-grill-2026-08-22.md](../design/analytics-and-replay-grill-2026-08-22.md).
