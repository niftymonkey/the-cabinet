# The tape format

A run's recording is one artifact, the tape: a format version and three byte-separable sections. The body holds the run's dice, its starting state and the steering the simulation consumed, tick by tick. The witness section is Hungry Grave ADR 0019's. The observations section holds runtime evidence. The tape is bytes and never a JSON string, sized so a full stage's tape stays a file somebody can hold and send, because sharing a run must not become a hosting problem.

The sections split by evidence class, and the split is the record-time rule (ruled by Mark 2026-08-23): deterministic, recomputable evidence is derived later from replay, and runtime, measured evidence is captured during the original run, because replay cannot recreate it. A tape replays exactly, so a question invented next year gets asked of a tape recorded today, and anything recomputable, entity counts and event volume included, is deliberately absent from the record, recovered by replaying to the tick instead. What was not captured at record time is lost from that run permanently, so the observations section is a general home for non-replayable evidence rather than a special case built for timings. The instrument's purposes are an open pool (Hungry Grave ADR 0021), and every format decision sits under its counterweight.

The version is a refusal contract, stated in the decoder: a reader refuses a version it does not know rather than guessing at a layout. The three evidence classes already known to be fundamental landed together in version 1, because adding one later would mean either abandoning compatibility with existing tapes or maintaining a second decode path forever, and the version is frozen for format changes only: tape compatibility never freezes gameplay tuning (ruled by Mark 2026-08-25). Which changes are the version's to carry, and which belong instead to the witness version or to identity recorded inside the tape, is Hungry Grave ADR 0043's.

Seven decisions this format obeys are their own records, all extracted from this file on 2026-08-26: a partial tape is a valid tape (Hungry Grave ADR 0026), the header records resolved values and never absences (ADR 0027), the run's outcome is orthogonal fields (ADR 0028), the tape holds exactly what the simulation consumed (ADR 0029), steering carries the simulation's own precision (ADR 0030), damage is attributed in both directions (ADR 0031), and the frame row (ADR 0032). The wire layout, byte order, header field list and decoder hardening live in the tape module and its tests, not here.
